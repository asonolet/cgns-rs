# cgns-rs

Rust bindings for [CGNS](https://cgns.org) (CFD General Notation System), the
ISO 10303-209 standard for storing and retrieving computational fluid dynamics
data. The underlying storage layer is HDF5.

## Project structure

| Crate | Description |
|---|---|---|
| [`cgns-sys`](cgns-sys/) | Raw `extern "C"` FFI bindings (auto-generated by `bindgen`) + thin safe helpers. |
| [`cgns`](cgns/) | High-level, idiomatic Rust API built on top of `cgns-sys`. |
| [`cgns-tools`](cgns-tools/) | `cargo install`-able CGNS CLI tools (`cgns-list`, `cgns-check`, `cgns-convert`, `cgns-diff`, `cgns-compress`, `cgns-names`). |

The two-crate layout follows the standard Rust FFI convention (like
`libgit2-sys`/`git2`, `openssl-sys`/`openssl`, `hdf5-sys`/`hdf5-metno`).

## Quick start

Add to your `Cargo.toml`:

```toml
[dependencies]
cgns = { git = "https://github.com/asonolet/cgns-rs" }
```

For low-level access (unsafe):

```toml
[dependencies]
cgns-sys = { git = "https://github.com/asonolet/cgns-rs" }
```

### Write a structured 3-D grid

```rust
use cgns::data::GridLocation;
use cgns::CgnsFile;

let file = CgnsFile::create("output.cgns")?;
let base = file.create_base("Base", 3, 3)?;
let zone = base.create_zone_structured("Zone", &[4, 3, 5, 3, 2, 4, 0, 0, 0])?;

zone.write_coord_f64("CoordinateX", &xs)?;
zone.write_coord_f64("CoordinateY", &ys)?;
zone.write_coord_f64("CoordinateZ", &zs)?;

let sol = zone.write_solution("Solution", GridLocation::Vertex)?;
sol.write_field_f64("Density", &field_data)?;
// file is auto-closed on drop
```

### Read data back

```rust
let file = CgnsFile::open("output.cgns")?;
let base = file.base("Base")?;
let zone = &base.zones()?[0];

let mut data = vec![0.0; 60];
zone.read_coord_f64("CoordinateX", &[1, 1, 1], &[4, 3, 5], &mut data)?;
```

See the [`basic_cgns` example](cgns-sys/examples/basic_cgns.rs) for a complete
write-then-read program.

## CLI tools

Six upstream CGNS command-line tools are packaged and can be installed with a single command:

```bash
cargo install cgns-tools
```

No system package manager or `sudo` required — they go straight into `~/.cargo/bin/`.

| Tool | Description |
|---|---|
| `cgns-list` | List CGNS file contents (tree structure) |
| `cgns-check` | Validate CGNS file correctness |
| `cgns-convert` | Convert between ADF and HDF5 file formats |
| `cgns-diff` | Diff two CGNS files |
| `cgns-compress` | Compress CGNS files |
| `cgns-names` | Print CGNS naming database (names, dimensions, units) |

## Prerequisites

- **CMake** ≥ 3.20
- **C compiler** (gcc, clang, MSVC)
- **curl** and **tar** (for downloading HDF5 source)

On Debian/Ubuntu:

```bash
sudo apt install cmake build-essential curl
```

## Build

A normal `cargo build` is sufficient — the build script automatically downloads
HDF5 1.14.6, compiles it as a static library, then compiles CGNS v4.5.2
(vendored as a git submodule).

The first build downloads HDF5 (~30 MB) and compiles both libraries, which
takes a few minutes. Subsequent builds are incremental.

### Using a system HDF5

```bash
export HDF5_DIR=/path/to/hdf5/installation
cargo build
```

The directory must contain `include/` and `lib/` with the HDF5 headers and
`libhdf5.a`. You can combine this with:

```bash
export CGNS_RS_NO_BUILD_HDF5=1
```

to skip the HDF5 download step entirely.

## Thread safety

The CGNS C library uses global state and is **not thread-safe**. This crate
serialises all FFI calls through a global `Mutex`. Safe wrappers acquire the
lock automatically — you can use `CgnsFile`, `Base`, `Zone`, etc. from
multiple threads without data races.

If you call raw FFI functions (`cgns_sys::cg_*`), you **must** acquire the
lock yourself via `cgns_sys::lock_cgns()`.

### `cgns-sys` — low-level (safe helpers + raw FFI)

All 300+ CGNS MLL functions are available as `unsafe extern "C"` via the
generated bindings. Thin safe wrappers exist for the most common operations
(open, close, base/zone/coord/sol/field read/write).

## Limitations

- Querying file metadata (`bases()`, `zone_count()`, etc.) requires the file
  to be opened in read mode. After writing, you must close the file (or let
  `Drop` close it) and reopen with `CgnsFile::open`.
- Only `f64` data is exposed in the high-level wrappers; integer and single-
  precision access requires raw FFI calls or `cgns-sys` helpers.
